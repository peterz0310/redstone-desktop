# Animated terrain and small scenery details

Water and lava animate in both the editor and Desktop. Trees, leaves, shrubs, mushrooms, flowers and reeds have a subtle light glint; their shape, position and terrain capabilities never change. Original procedural liquid artwork is included, so the feature works without any game installation. Java imports use local `water_still.png` and `lava_still.png` strips and their frame metadata. No new game artwork is bundled.

To enable the game's animation for an older import, open Appearance & Packs → More options & custom packs → Refresh Imported Minecraft Assets. Previous caches retained only frame zero, so Reload cannot recover the rest. Missing lava art or animation falls back to original artwork. A deliberately static custom liquid texture stays static. macOS Accessibility → Display → Reduce motion freezes liquids on their first sequence frame and disables glints; changes apply while the app runs. Library thumbnails and the old diagnostic fixture terrain remain static; generated worlds and their painted terrain animate.

## Renderer ownership and cost

`TextureAnimationSpec` and `AnimatedRaster` validate data and resolve frame timing without SpriteKit. Java import translates a limited `.png.mcmeta` animation object into optional format-1 manifest data. [Java import](JAVA_TEXTURE_IMPORT.md) and [resource packs](RESOURCE_PACKS.md) document exact limits and fallback behavior. No expressions, executable pack code or custom pack shaders are accepted.

`TerrainAmbience` resamples validated liquid frames into one nearest-filtered **48×1024 RGBA atlas** per renderer asset revision: three 16-pixel columns, each with room for 64 frames. Transparent liquid frames are backed by an opaque liquid color. Tile-sized masks are cached with the semantic tile artwork, then row-copied into chunks; chunk creation does not recalculate pixel masks. A visible animated chunk retains one mask at the existing terrain raster resolution (256×256 original / 512×512 imported), plus its existing baked texture. Mask red distinguishes shallow/deep/lava pixels; green identifies decorated pixels for glints. Decoration pixels over water remain baked, so reeds are preserved. Empty terrain remains transparent. The shader samples exact texel centers for both baked terrain and its semantic mask; it does not rely on texture filtering flags inside shader sampling. This keeps ground/decoration pixels crisp and prevents mask interpolation from bleeding animation across their edges. Liquid frames also use explicit texel-center sampling. SpriteKit’s node color/alpha is applied after animation.

Each chunk still has one sprite and no per-tile animation nodes. The renderer attaches an app-owned [public SpriteKit fragment shader](https://developer.apple.com/documentation/spritekit/creating-a-custom-fragment-shader). Shared [SKUniform](https://developer.apple.com/documentation/spritekit/skuniform) objects update frame indices/interpolation/time at most 20 times per second from `DesktopScene.update`. All chunks use the same phases. Atlas creation happens only on asset revision, masks/textures only on chunk creation or terrain changes. Camera/circuit/Finder updates do not restart the sequence; animation ticks never mutate world data, invalidate terrain caches, publish SwiftUI state or execute actions. Bounded GPU frame sampling replaces per-frame CPU image baking. Skipped updates select the current phase rather than replaying a backlog.

Reduce Motion is cached from the public NSWorkspace accessibility setting and its change notification; the renderer does not poll Finder or system window lists for animation. CoordinateMapper remains responsible for world/screen placement. `LavaPool` is pure deterministic terrain generation, independent of the renderer and clock. Lava behaves like other liquids for placement; it does not cause heat, damage, spreading or file actions.

## Verification

`TerrainAnimationTests` checks bounded metadata, reordered/repeated frames, interpolation/looping, original opaque frames, format-1 loading/fallback, and unchanged chunk/node/texture metrics over 1,000 animation updates. An offscreen native `SKView.texture(from:)` test exercises the actual shader and verifies red/green imported frames and Reduce Motion freeze from rendered pixels. A checker-pattern regression reproduces the static shader blur, then verifies that corrected terrain matches a nearest-filtered sprite with zero mixed red/blue pixels and preserved node alpha. `JavaTextureImportTests` checks original synthetic animated-strip imports, fixed tints and cache round trips. `LavaPoolTests` checks rare eligible pools, chunk/direct agreement, connected footprints, brush persistence and circuit protection. Placement tests reject every component on every liquid.

The locally installed Java 1.21.8 JAR was imported into a temporary cache and reloaded without modifying active preferences or world saves: water's 32 frames and lava's 20-frame/38-step sequence were preserved. Temporary game images were removed after this validation. Real desktop appearance, panning and accessibility changes remain the owner's [Mac acceptance checks](TESTING.md).
